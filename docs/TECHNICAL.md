## Executable and memory
- `1ST_READ.BIN` (1,806,116 bytes) is plain SH-4 code loaded at `0x8C010000` (file offset + 0x8C010000 = address),
  *from the code*. The memory after its end (0x8C1C8F24...) is the game's own data and heap: the file can not grow.
- The Japanese text of the executable lies in `0xB9700-0xCF000` (file offsets): error and network messages, a
  pointer table of ~600 move names at `0xC2154` (4-byte entries), the wrestler roster and its group names (pointer
  tables at `0xCF87C...`), edit-menu labels, printf formats, and the name-entry keyboards (strings pointed to from
  `0xD6940-0xD69C0` and `0xD73F0-0xD7430`: they stay). Strings are NUL-terminated Shift-JIS padded to 4 bytes and
  pointed to by aligned 32-bit words (literal pools and tables): `tools/gametext.py` finds the pointers by value.
  `0xCDC34-0xCEA2F` holds the champion histories (fixed records, below), not pointed-to strings.
- The main menu's STRINGS.PAC loads at `0x8C6EDBA0` (seen headless).

## Archives and compression
`.PAC` (*verified*): `u32 n`, `n` absolute section offsets; a section is a table of entries - *counted*
(`u32 count`, offsets) or *plain* (offsets, count = first offset / 4) - with offsets relative to the section start
(`tools/pac.py ls`). No compression was found. SFD movies (`/MENU/*.SFD`) and the SOUND folder stay untouched.
`MENU/MENU.PAC` sections 1-4 are Ninja (NJCM) models.

## Text
- **Drawing** (*verified in game*): the game's own fixed-pitch font draws ASCII at half the width of a full-width
  Japanese character. English works in every text path tried, no font work needed: a 20-glyph Japanese line is a
  40-letter English line. Names and menu help use this font; the many menu *labels* are textures (below).
- `MENU/STRINGS.PAC` and `EDIT/STRINGS.PAC` (*verified*): `1`, `8`, then a plain table (3200 / 2700 entries) and the
  string pool; entries are Shift-JIS, NUL-terminated, read by index. Menu table: a real `0x0A` between lines; Edit
  table: the two characters `\n`. 3141 / 2559 used entries. `tools/gametext.py` reads, dumps and rebuilds them (byte
  identical round trip). The game loads only `MENU/STRINGS.PAC`, also in Edit mode (*seen headless*, 2026-11-07);
  `EDIT/STRINGS.PAC` is an older, unused version of it (translated anyway; [HIDDEN_CONTENT.md](HIDDEN_CONTENT.md)).
- Executable strings: `translation/text/exe.txt`, written in place; a string that outgrows its slot makes the run of
  neighbouring pointed-to strings repack (pointers rewritten); a fixed record string must fit. `gametext.py exe_step`.
- Not text: `IDSTR_*` ids and a few garbage hits (`0C38A4`, `0C4928`, ...) stay without English.
- Room: the text boxes were not measured screen by screen. `# fit` per block = description box 40 letters x 2 lines,
  short names = max(16, Japanese width in cells). Known tight fields (*seen headless*): option values in the rule
  screen (brackets are as wide as the widest Japanese value), edit-menu labels (6 letters), main option labels.

- **Name entry** (*from the code*; patch *verified in game* in test4: wrestler name, 16 letters, in a match): one editor class (constructor `0x8C095CC0`,
  `editor(obj, cells 1..20, help id, help id)`, 0xD0 bytes) works in full-width cells: buffer at +0x50 (cells padded
  with `0x8140`, end byte at cells x 2), cell count at +0xC8, output pointer at +0x84 (setText `0x8C096B56`; OK copies
  the buffer there and blanks trailing spaces). Its keyboards are the strings at `0xBFC10...` (table `0xD694C`, 3
  groups x 7 rows per page; the ABC/123 page types full-width Ａ, ２, ！...). Edit mode uses it twice, each from a
  28-byte parent that keeps a copy of the name at +8: the wrestler name (record `0x8C28236C` + 0x47A, 16 bytes + end;
  parent vtable `0x8C0EFAE8`, setup `0x8C096E56`, update `0x8C096FA2`) and the Thinking pattern names (17-byte slots at
  `0x8C282840`, slot number at `0x8C282E40`; vtable `0x8C0EFB00`). Both asked for 8 cells, so only 8 English letters
  fit. `tools/nameentry.py` (always on in the English build) asks for 16 cells, enlarges the parents to 44 bytes, loads
  stored ASCII back as full-width cells and stores full-width letters, digits and common symbols as ASCII, packed into
  the 16 bytes (kana and kanji 2 bytes each; what doesn't fit is dropped). Controls: A types, B goes to the button bar
  (Hiragana / Katakana / ABC/123 / Kanji / OK), L/R move the name cursor. A third user (vtable `0x8C0EFB18`, cells
  from its caller) is unchanged.

## Images
- Textures (*verified*): PAC entries with a 16-byte header `u32 id, u8 pixel format, u8 layout, u16 0, u32 w, u32 h`
  then PVR data (formats of `tools/pvr.py`: ARGB1555 / RGB565 / ARGB4444; twiddled, rectangle, VQ, VQ + mipmaps).
  VQ + mipmaps (layout 4): codebook, then the levels 1x1 first up to w/2 (a 1x1 level takes 1 byte, 2x2 one byte), the
  full level, 10 bytes of padding. `tools/gfx.py` exports and imports them; VQ ones are encoded at edit time (numpy) and
  frozen (`translation/images-frozen`).
- Menu labels are 128x128 textures drawn on a quad about 4x wider than tall (tall, narrow Japanese); `tools/imgtext.py`
  renders English on a 4:1 canvas and squeezes it. Atlases (`ENTDATA/TELOP.PAC`: match banners, round names, time limits)
  and multi-row headings are redrawn row by row from boxes in `graphics.csv`.
- Kept Japanese: the title logo (MENU_MENU.0.065, pending the owner), movies, credits.
- The Edit Settings "複製" (Copy) button is MENU_MENU.0.113 (MENU.PAC section 0 entry 113, file offset 0xFD220, 32x32
  ARGB4444 twiddled). Its RGB is the button; its alpha is an unrelated mask reading セーブ, so with alpha applied it looked
  garbled. The game draws it opaque (*seen headless*). The English keeps the original alpha (`keep alpha` in graphics.csv).
- One text size (owner, 2026-11-07): `tools/imgtext.py` draws every one-line menu label at the size the longest needs, and
  every beveled 32x32 button (New, Edit, OK, Copy...) as a flat plate with the original frame and text at one size
  (`BUTTON_FS`; longer words shrink to fit). The button is shown about 2 x 1.45 times its texel size.
- The 1ST_READ.BIN short wrestler names (character select, match HUD) must stay within 16 letters: a 20-letter name
  garbled the HUD name plate (*verified in game*, 2026-11-07).

## Edit screen layout

The Edit Settings sub-screens draw a label and then its values with printf in character cells (a letter = 1 cell, a
Japanese character = 2), and the cursor box is placed and sized for the Japanese cells. English has to keep those widths
(*seen headless*, test5, 2026-11-07; original and build compared screen by screen, `private/work/sweep/40-edit-screens.steps`):

- Fixed-width labels: the Parameter names are a 12-cell field (`%s   [%s]   [%s]`), the HP names 6 cells (`%s  [%6ld]`),
  the Thinking Pattern name label 18 cells (`%s  ［%-16s］`). `# field N` on a STRINGS.PAC block makes the build pad
  the English to N letters (tools/gametext.py; lint checks the length).
- Parameter values are digit strings from the 1ST_READ.BIN digit table: full-width in Japanese (［３］ = 4 cells), one
  letter in English. The format at 0x8C0CFA48 becomes `%s   [ %s]   [ %s]` (build.py CODE_PATCHES, group `layout`).
- `［詳細］` is 8 cells and so is the cursor: the English button is `[Detail]`.
- The Critical Setup heading (MENU STRINGS 0831) is centred with leading spaces, like the Japanese.
- Move Setup category plates (MENU_MENU.0.133-136, 64x16 rows) come from the icon table 0x8C0E2924: 13 entries of 20
  bytes (`u16 w, h; s16 xoff, yoff; u16 u0, v0, u1, v1, texture, pad`), indexed by the move's type byte (table
  0x8C0E2A28) minus 1, drawn at the name's x minus xoff. The original xoffs are 0, -20 ... -240, so each category
  sits 20 px further right than the one before (*from the code*, read at 0x8C09018A; one reference). Kept as in
  the original (owner, 2026-11-07); setting all xoffs to 0 would put every plate over the start of the name.

## Champion histories
*From the code*, screens *seen headless* (2026-11-07, original and build). Twelve tables of fixed records in
`1ST_READ.BIN`, each copied whole (memcpy, e.g. 0x8C071C20: 0x290 bytes from `0xCDC34` to `obj+0x338`, 0xD2 bytes
from `0xCDEC4` to `obj+0x5C8`) - no pointers to single records. Text: `translation/text/champions.csv`
(`tools/records.py` TABLES, one row per name shared by every table).
- Champion / winner record, 41 bytes: `u8` number (No.), `u8` defences (V), 4 wrestler ids of the current holder
  (`FF` = a past holder; the current one has its ids, e.g. `15 FF FF FF` Muto, `0C 0D FF FF` Goto & Ohara), name
  (35 bytes, Shift-JIS or ASCII, NUL-padded).
- Title-defence record of the current holder, 42 bytes: `u16` finishing move, `u8` index, `u8` minutes, `u8`
  seconds, `FF FF`, name (35 bytes). Shown as "Won <name>" / "V1 <name>" and "31 min 38 sec <move>".
- Tables (file offset, records): IWGP Heavyweight `0xCDC34` 16 (No.9-24) + defences `0xCDEC4` 5; IWGP Tag
  `0xCDF96` 16 + `0xCE226` 2; IWGP Jr. Heavyweight `0xCE27A` 16 + `0xCE50A` 4; IWGP Jr. Tag `0xCE5B2` 4 + `0xCE656` 1;
  G1 Climax `0xCE680` 8; Best of the Super Juniors `0xCE7C8` 6; Super Jr. Tag League `0xCE8BE` 1; SG Tag League
  `0xCE8E7` 8. Screens: IWGP Title Match > belt > Singles/Tag > Past Champions (A: Title Records); Series Match >
  tournament > Past Champions.
- Room: Past Champions draws "No.18 <name>" with the name at x=132 and the V column at a fixed x=482, 12 px a
  letter: 28 letters (the build checks it). Title Records and the tournament lists have more.
- The old exe.txt dump took these names as strings starting at the `FF` bytes, so the English overwrote the 4 id
  bytes and the game, reading the name 4 bytes later, showed "hiro Chono" (round 2). Fixed by the records table.

## Crowd rush (comeback state)
*From the code* (1ST_READ.BIN), trigger also *seen headless* (Liger vs Hashimoto exhibition, original image).
- Every wrestler object has a status object at `wrestler+0x84` (heap, e.g. 0x8C5A08A0 in one match;
  `status+0` points back to the wrestler, `wrestler+0x64` is the opponent, `wrestler+0xC5` the slot).
  Status fields: `+0x10..+0x20` maxima, `+0x24` current stamina (the main health value), `+0x38` lowest
  stamina % reached, `+0xDE` stamina %, `+0x84` short-term damage pool, `+0x9C` (u16) hits taken in a
  row, `+0x9E` (u16) rush timer in frames, `+0xD5` copy of "timer running", `+0xB5` eliminated.
- Counter: the damage routines (0x8C03E990, and the one around 0x8C03DA00) add 1 to the victim's
  `+0x9C` for each hit from another slot, and set the attacker's `+0x9C` to 0: it counts hits taken
  without hitting back.
- Trigger, 0x8C0408D8 (run every frame for every wrestler from 0x8C03D56E): when no rush is running, the
  counter is at least 8 and the wrestler's current stamina `+0x24` is lower than the opponent's, it
  sets `+0x9E` = 1800 (30 seconds) and clears the counter. In the 4-wrestler mode (`0x8C1E15B2` = 2) it
  also fires when all three others target this wrestler. A special-match id 54 in `0x8C1E158C` starts
  a wrestler with the rush (0x8C024F10). No test of corner, controller (player/CPU) or wrestler stat.
- While `+0x9E` > 0 it counts down and the counter stays 0. Effects read from the code: stamina
  regeneration +1 per frame (0x8C03E4E0); the damage pool `+0x84` fills half as fast and drains twice
  as fast (0x8C03E684, 0x8C03EB5E, 0x8C03DC5C); stamina damage x1.5 in both damage routines (taken in
  0x8C03E990, dealt in the other - the two check opposite sides, cause unknown); a different action id
  (0x1A9 instead of 0x1A8) at 0x8C038BD6. The HUD name cycles white/red/blue/green while it runs
  (*seen headless*). The pin kick-out routine and the chant sound were not traced.
